01 / The extra multiplier

What is a Spec Aura?

A specialization aura is a passive spell record used to adjust abilities for a specialization. It can carry several separate rules. In this calculator, Spec PvP Aura specifically means the specialization's PvP tuning rules. Ordinary specialization passives, which may also change a spell's baseline damage or cooldown, are a separate layer.

It has a defined scope

A rule must match the source spell through its affected-spell list or an exact-build spell label. The effect must also match the rule's type: direct damage or healing, periodic output, absorption, or a specified effect number. The engine does not spread that multiplier across every number in a talent's text.

It can reach a triggered spell

A talent may describe damage performed by another spell. Explicit trigger and tooltip references connect the talent to that effect. The multiplier applies to that effect's value; proc chance, duration, target count, and unrelated talent bonuses keep their own rules.

Aura factor = 1 + percentage / 100
Final factor = Spell PvP × Aura factor₁ × Aura factor₂ × …

For example, +1% becomes ×1.01; −20% becomes ×0.8. Applicable aura factors multiply. With no applicable rule, the aura factor is ×1. A spell coefficient of ×1 can still produce a PvP difference through an aura.

Implementation: aura normalization, matching, and multiplication.

02 / Follow the evidence

Why does Wildfire Imbuement gain 1%?

In the inspected snapshot (spell build 12.1.0.69875), talent 1252943 references damage spell 1252966, effect #1. Its spell PvP coefficient is ×1. Survival PvP aura 1256941, game effect ID 1264706, supplies +1% to matching direct output. The aura source reports build 12.1.0.69587; this is shown separately from the spell build. The inspected exact-build SimulationCraft Hunter dump also contains effect 1264706 with value 1 and lists both 1252966 and 1262293 as affected spells.

40% AP × 1 × 1.01 = 40.4% AP

That explains the extra damage. It does not increase the 10-second duration or the proc rate. See Drustvar's Hunter aura records for the rule and affected spells. Source links are live; the example describes the recorded snapshot, not a promise that future patches keep these values.

Raptor Swipe combines two modifiers

Talent 1259003 references 1262293, effect #1. The spell coefficient is ×1.2 and the same direct-output aura contributes ×1.01:

280% AP × 1.2 × 1.01 = 339.36% AP
Total increase: 21.2%

These are datamined explanations of the calculation. They do not establish Blizzard's design reason for choosing a particular percentage.

04 / Inside the project

From source records to a readable tooltip

  1. Discover the trees. Raidbots supplies the available specializations and graph. Coordinates and edges come from the same geometry in the UI.
  2. Collect spell evidence. The Python source adapters fetch and cache tooltip, effect, and aura records. SimulationCraft data must match the tree's build.
  3. Resolve concrete effects. The pipeline compares effect identities and semantics. Dependencies follow explicit triggers, formulas, and description references. Reverse “Affected Spells” lists alone do not create talent dependency paths. Inactive equipment-only conditional branches are excluded: an old tier-set bonus is not an unconditional hero talent modifier. A direct tooltip-value reference takes priority over a parallel runtime trigger.
  4. Apply scoped modifiers. The matching spell coefficient and PvP aura rules produce an effect-level multiplier. A generic talent parameter does not inherit an output aura merely because it mentions that spell.
  5. Resolve ranks and text. TraitDefinition set, multiply, and add overrides establish rank values. The renderer changes matched expressions, keeps character-dependent formulas symbolic, and preserves unrelated numbers. Every rank has its own full description and PvP changes. The selected rank is marked Current. Apex progression is split into all four ranks, including the two separate ranks of its middle stage.
  6. Validate and publish. All specializations must pass before the generated JSON/JavaScript snapshots are committed and GitHub Pages is updated. A failed run leaves the previous deployment available.

Import, export, and share

Import accepts a current in-game talent string or a link from this calculator. Export provides both formats. Your URL updates with talent choices and the PvE/PvP mode, so a refresh restores the build. Opening the site without a build shows the class and specialization chooser.

The codec follows Blizzard’s ClassTalentImportExport implementation (community source mirror): serialization version 2, specialization ID, a zero tree hash allowed for third-party tools, and the full ordered node list, including inactive nodes. Choices, partial ranks, granted nodes, and hero-tree selection are encoded separately. Strings from a different patch can be incompatible; unavailable nodes, invalid ranks, missing prerequisites, and point-limit violations are rejected.

05 / Trust, with context

What gets checked?

Data edge cases

  • Missing or conflicting evidence, unresolved rank expressions, and malformed tooltip fragments block publication.
  • Old Drustvar observations are superseded only when current Wowhead and exact-build SimC corroborate the same effect.
  • Zero base values must not erase real spell-power coefficients.
  • Direct, periodic, absorb, label-scoped, and effect-specific aura rules are matched separately.
  • True choices and tiered Apex progression retain distinct behavior.

Browser behavior

  • Every specialization and hero tree is checked at 2560, 1440, 1024, 390, and 320 pixels.
  • Line endpoints are compared against actual node centers.
  • Rank transitions, point gates, full descriptions, comparisons, and touch controls are exercised.
  • JSON and JavaScript datasets must agree before publishing.

How to read the colors

PvP buff means a beneficial change. PvP nerf means a detrimental change. Mixed / other change means opposing effects or a change whose benefit cannot be confidently classified from the description. Color describes PvP versus PvE in this snapshot, not a change since the previous patch.

VERIFIED means the automated source and rendering checks passed. It does not mean every interaction was tested in-game. Source lag, unannounced server behavior, gear, haste, versatility, and conditional interactions can affect real combat results. The mechanics view exposes evidence and source versions so those limits remain inspectable.
